# 知天下 AI 问答演示前端

这是从另一台 Mac 的源码快照导入的独立演示应用，包含问答页、同源 Node BFF、模拟测试和后续 A/B/C 规划。原始导出背景见 [HANDOFF.md](HANDOFF.md)；其中关于 SSH 隧道的步骤只适用于原机器，不是 Air 本机启动要求。

## 与 Provider A 的关系

本应用是知天下的品牌网站，不是 Provider A 的 fork。Provider A 独立管理授权账号、IMA 会话、调度和问答；本应用独立管理页面、网站身份和业务后端。两个服务通过有版本约束的接口连接，不共享账号库、运行目录或凭证文件。本应用暂按私有仓库维护；不要把整个根项目推到 [Provider A 公开仓库](https://github.com/19Chris19/ima-qa-web-agent)。

```text
浏览器 → 业务网站前端 → 业务网站后端 (BFF) → Provider A → IMA
                                    ├─ 普通 token：会话历史
                                    └─ 服务 token：原生 Agent 容量与流式问答
```

| Provider A 版本 | 本应用真实问答兼容性 |
| --- | --- |
| v0.3.1 及更早版本 | 不兼容本应用使用的带键内部 SSE；不能仅凭健康检查宣称已接通。 |
| [v0.4.0](https://github.com/19Chris19/ima-qa-web-agent/releases/tag/v0.4.0) | 本应用固定依赖的公开版本；合成合同测试通过，启动及派发前还会校验 `knowledge_agent_keyed_sse_v1`。维护者尚未对该 tag 完成隔离账号的真实 IMA 复验。 |

如需使用后续 Provider A 补丁版本，先确认受保护的容量接口仍声明同一合同，并在隔离环境按[接入指南](./docs/PROVIDER_A_WEB_INTEGRATION.md)完成真实一问一追问。`v0.4.0` 的发布不会自动替换本机正在运行的 3117；本网站也没有因此上线主站。

拆为独立私有仓库时，只导出本目录的源码、合成测试和文档；排除 `.env.local`、`runtime/`、`dist/`、账号信息与真实会话。正式网站还必须替换本机原型 `/admin`、接入自身用户认证并审查公网反代策略。公开网站仓库与发布许可是后续独立决策。

## 在 Provider A 所在的 Air 上预览

需要 Node.js 20 或更新版本。演示服务默认监听 `127.0.0.1:4317`，默认从服务端连接 `127.0.0.1:3117`；不会启动第二套 Provider A，也不需要重新扫码。

```sh
cd apps/explorer-ai-qa-demo
npm ci
npm test
npm run build
npm start
```

打开 `http://127.0.0.1:4317/`。真实原生知识库问答需要普通 API token、独立内部服务 token 和目标知识库范围摘要，均保存在 Git 忽略的 `.env.local`（权限 `0600`）。在 Provider A 所在机器上运行：

```sh
npm run configure:local -- --provider-env /你的私有/provider-a.env
npm start
```

接入脚本读取 Provider A 的私有部署配置，不打印凭证或知识库 ID。另一台机器需要先通过 SSH 隧道访问 Provider A，再在自身后端安全配置这三项；管理员 token 不参与业务问答。服务端适配代码、接口与远程配置见 [网站接入指南](./docs/PROVIDER_A_WEB_INTEGRATION.md)。

`/api/qa/health` 分开报告连接、两类鉴权、原生 Agent 容量和本进程最近完成的真实问答。检查接口不会自动提问。完成配置后可显式运行 `npm run verify:real`：它经演示网页后端串行发起一问一追问，只输出脱敏事件计数与耗时。知识库来源和正文均由真实 IMA 回答提供。

历史会话仍能阅读。升级前创建的会话在演示页中为只读；请新建会话后使用原生知识库 Agent 继续提问。新会话归属和请求去重记录只保存在本应用 Git 忽略的 `runtime/`；去重记录不保存问题或回答原文。取消或断流后请先查看会话历史，不要直接重发相同请求。

## 回答期间继续提问

当前回答还在生成时，可以在同一个输入框里写下一问。输入文字后，主按钮从“停止回答”变成“加入队列”；输入框为空时仍是“停止回答”。待发问题显示在输入框上方，派发前可以编辑或删除。只有上一轮完整成功结束，服务端才会按顺序自动派发下一问；上一轮中断、失败或服务重启后，待发问题暂停，必须由用户处理，不会自动重试或改变正在生成的回答。同一会话最多暂存 3 条。

待发问题原文临时保存在本应用 Git 忽略的 `runtime/queued-turns.json`，文件权限为 `0600`，一小时后过期；不要将该目录发布或备份到公开位置。队列按浏览器身份和会话隔离，不额外增加 Provider A 的账号并发容量。

## 回答格式与媒体边界

网页累积 Provider A 的原始 `delta` 文本，用同一套 GFM 解析与 HTML 清理流程展示流式、完成态和历史。依赖随 `npm ci` 安装，并从本站同源加载，不使用 CDN。结构完整的 Markdown 表格可横向滚动；列关系不确定时按原文分行展示，不猜测单元格，也不附加格式诊断或原文展开入口。只隐藏能对应结构化来源的引用编号，普通数字和代码不改写。中断的回答保留已收到正文并标记未完成。

当前 IMA Web Agent 问答流没有已验证的生图请求及图片返回合同。网页不请求任意上游媒体 URL，也不开放生图入口；收到 Markdown 图片语法时仅显示不支持提示。IMA 产品具备生图能力不能等同于这个 Web Agent 协议已可接入。

`/admin` 是**无管理员鉴权的信息架构原型**，不是 Provider A 的账号管理页，不得对公网发布。正式账号管理仍使用 Provider A 受保护的 `/admin.html`。本演示应用仅监听本机；接入正式网站前，还需以网站登录身份替换匿名演示 Cookie，并完成权限和反向代理审查。代码仓库设为私有并不等于网站具备生产访问控制。
