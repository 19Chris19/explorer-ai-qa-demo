> 包含持久任务、长回答与断线续接，以及[发布前性能优化](./docs/FRONTEND_PERFORMANCE_20261010.md)；旧 RC tag 保留，不追随浮动 main。
> 合成验收、发布版本、运行服务必须分别确认，不能直接用旧镜像搭配本分支网页。
> 当前 Air / Docker / 在线入口与健康抖动见[最新验收记录](./docs/RELEASE_ACCEPTANCE_20261010.md)；本次发布未额外进行真实 IMA 问答。

本仓库交付品牌问答页和同源网站后端（BFF），通过独立的 Provider A 服务使用腾讯 IMA 知识库。**部署知天下只从本仓库进入：安装工具准备匹配的 Provider A，不需要你手工拼接两个项目，也不依赖维护者的 Air。**

## 一套产品，两个分工明确的仓库

```text
访客浏览器 → 网站入口 Nginx → 知天下网页 / BFF → Provider A → 腾讯 IMA
                              网站身份、待发队列    账号、会话、调度
                                   独立数据卷        独立数据卷
维护电脑 → 官方扫码窗口 → Provider 管理接口 → 加密账号库（服务端）
```

默认一个 Compose 项目启动网关、网站和专用 Provider 三个容器，可以全部在一台机器上运行。回答沿原路流式返回，浏览器不取得 Provider 凭证；扫码浏览器只用于维护，不是每轮问答的运行依赖。Provider 的公共通用问答页可以单独使用；知天下的品牌网页不是其 fork，也不包含第二份 IMA 登录实现。

两仓分开开发，整套部署按配套版本交付。共用既有 Provider（例如机器人账号池）是高级接入：并发额度、维护窗口和故障会互相影响，不能自动绑定现有 Air 服务。

## Agent 安装与扫码接入

这是新安装的唯一推荐入口。预设“3DGS 知识答疑”分享链接，也支持显式配置其他官方分享链接。先准备私有仓库和私有镜像拉取权限、Docker 与 Git，再交给 Agent；需要扫码、手机确认或加入知识库时由人完成。

**稳定 v0.3.0 固定依赖 Provider v0.5.0。** 新安装选择最新非预发布 Release，核对两边的不可变镜像清单；发布前的 main 或仅有 tag 的候选不算完整交付。历史 v0.2.1/v0.4.2 和 RC 配对见各自 tag，不混改旧安装。

完整流程见 [Agent 部署说明](./docs/AGENT_DEPLOYMENT.md)。[配套清单](./deploy/bundle.env)统一选择版本；[版本与候选门槛](./docs/DEPLOYMENT_MODEL.md)解释镜像摘要、独立部署和发布顺序。

> 请部署此私有仓库最新已发布稳定版本，先读 README 与 docs/AGENT_DEPLOYMENT.md。检查私有仓库及镜像权限、系统、Docker、端口和已有安装，使用仓库引导工具部署网站与匹配的 Provider A；默认知识库为“3DGS 知识答疑”。不要输出凭证、覆盖账号或会话，不开放管理/内部接口。需要扫码、手机确认、加入知识库、服务器信息或系统授权时暂停。完成后报告版本、网站地址、扫码接入状态、未通过项目与恢复方式；真实一问一追问须先授权，不把服务启动当成问答成功。

## 高级部署与开发

手工 Node、共用已部署 Provider 和历史源码 Docker 路径见[高级部署](./docs/ADVANCED_DEPLOYMENT.md)。这不是首次安装的必做步骤，不应从 Air 复制账号或要求普通使用者手工找数字 ID。原始导出背景 [HANDOFF.md](HANDOFF.md) 仅供开发溯源。

`/api/qa/health` 分开报告连接、两类鉴权、原生 Agent 容量和本进程最近完成的真实问答。检查接口不会自动提问。完成配置后可显式运行 `npm run verify:real`：它经演示网页后端串行发起一问一追问，只输出脱敏事件计数与耗时。知识库来源和正文均由真实 IMA 回答提供。

历史会话仍能阅读。升级前创建的会话在演示页中为只读；请新建会话后使用原生知识库 Agent 继续提问。新会话归属和请求去重记录只保存在本应用 Git 忽略的 `runtime/`；去重记录不保存问题或回答原文。取消或断流后请先查看会话历史，不要直接重发相同请求。

## 回答期间继续提问

当前回答还在生成时，可以在同一个输入框里写下一问。输入文字后，主按钮从“停止回答”变成“加入队列”；输入框为空时仍是“停止回答”。待发问题显示在输入框上方，派发前可以编辑或删除。只有上一轮完整成功结束，服务端才会按顺序自动派发下一问；上一轮中断、失败或服务重启后，待发问题暂停，必须由用户处理，不会自动重试或改变正在生成的回答。同一会话最多暂存 3 条。

待发问题原文临时保存在本应用 Git 忽略的 `runtime/queued-turns.json`，文件权限为 `0600`。未启用维护控制时沿用一小时过期规则；配置维护控制后，过期项保留为暂停状态，并阻止排空确认，不能通过等待过期来清掉待发工作。不要将该目录发布或备份到公开位置。队列按浏览器身份和会话隔离，不额外增加 Provider A 的账号并发容量。

本版本包含[私有维护排空](./docs/MAINTENANCE_DRAIN.md)：拒绝新提交的同时允许已有回答和已准入队列收尾，异常队列存储拒绝启动，不静默丢弃消息。功能需要逐实例配置，运行服务不会因发布自动获得它；首次安装仍须单独确认停机边界，不能用健康检查代替排空证明。

## 回答格式与媒体边界

网页累积 Provider A 的原始 `delta` 文本，用同一套 GFM 解析与 HTML 清理流程展示流式、完成态和历史。依赖随 `npm ci` 安装，并从本站同源加载，不使用 CDN。结构完整的 Markdown 表格可横向滚动；列关系不确定时按原文分行展示，不猜测单元格，也不附加格式诊断或原文展开入口。只隐藏能对应结构化来源的引用编号，普通数字和代码不改写。中断的回答保留已收到正文并标记未完成。

当前 IMA Web Agent 问答流没有已验证的生图请求及图片返回合同。网页不请求任意上游媒体 URL，也不开放生图入口；收到 Markdown 图片语法时仅显示不支持提示。IMA 产品具备生图能力不能等同于这个 Web Agent 协议已可接入。

`/admin` 是**无管理员鉴权的信息架构原型**，不是 Provider A 的账号管理页，不得对公网发布。正式账号管理仍使用 Provider A 受保护的 `/admin.html`。本演示应用仅监听本机；接入正式网站前，还需以网站登录身份替换匿名演示 Cookie，并完成权限和反向代理审查。代码仓库设为私有并不等于网站具备生产访问控制。
