# 知天下 v0.2.1 发布说明

本文是发布准备稿。以正式 Release、固定 tag 和通过验收的镜像清单共同确认可安装版本，不以本文或服务健康检查代替验收。

## 交付关系

浏览器 → 知天下同源 BFF → Provider A → IMA。

知天下是独立的私有网站应用，不是 Provider 的 fork，也不包含第二份 Provider 源码。安装入口读取 `deploy/bundle.env`，固定使用 Provider A `v0.4.2` 的工具和镜像；正式清单同时记录两个镜像摘要与源码提交。不让部署者自行组合两个浮动最新版。

同一版本提供 Node 源码部署与 Docker 部署。网站镜像是私有的，拉取前需要仓库及镜像访问权限；Provider 镜像公开。新安装生成自己的私有配置、账号卷和会话卷，不依赖维护者的 Air，也不附带任何账号。

## 本版内容

- 单一扫码部署入口、固定版本工具委托、镜像与安装归属校验。
- 重复安装保护，拒绝覆盖已有配置或擅自接管遗留数据卷。
- 保留现有品牌问答体验、流式渲染、复制、队列及历史功能。
- 本地配置更新保留无关配置；归档合同与 Provider 导出工具对齐。
- 浏览器只访问网站 BFF，网站入口封锁 Provider 管理和内部接口。

## 安装与升级

1. 从本 Release 的固定源码开始，阅读 `docs/AGENT_DEPLOYMENT.md`。准备镜像访问权限和官方知识库分享链接；扫码、手机确认、加入知识库由本人操作。
2. 新安装使用 `onboard.sh` 或 `onboard.ps1`。已有安装不要重新初始化；先记录当前版本并安全备份私有配置与数据。
3. Docker 网站升级先确认队列空闲，使用 `sh deploy.sh upgrade REVIEWED_WEBSITE_DIGEST`。Node 部署使用独立固定源码产物、保留原私有配置与持久目录后安排维护窗口。
4. Provider 升级另行检查并安排窗口，网站升级不顺带重启 Provider、账号维护助手或机器人。
5. 核对协议、容量、历史、流式完成和管理路径封锁。真实首问及追问须明确授权；容量 0 表示已接通但无可用账号，不是可问答成功。

## 回退

Docker 网站使用已记录的前一版本和 `sh deploy.sh rollback`；Node 切回先前的兼容产物。先停旧写入进程，保留当前会话和队列数据，不能用旧备份覆盖升级后新增记录。Provider 账号迁移与回退不属于网站回退。

## 验收边界

当前候选的干净 ARM64 安装、空账号池检查、重复安装保护和合成流式 CI 已有记录，见 `docs/ONBOARDING_ACCEPTANCE.md`。最终 tag、双平台镜像及发布后安装以 Release 附件为准。未验收的 Windows 真机、远程 SSH 扫码、新账号真实首问与追问、长期续期和 Linux 长期运行不能以合成结果替代。不会自动更新现有 Air、Docker 演示或 Vercel 的运行服务。
