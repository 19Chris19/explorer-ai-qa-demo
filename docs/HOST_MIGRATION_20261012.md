# Air → M1 Max：完整服务迁移与在线恢复记录

日期：2026-10-12。此记录是既有安装的维护验收，不是全新安装、镜像发布或跨平台验收。供同事体验的说明见[体验与部署指南](EXPERIENCE_AND_DEPLOYMENT_GUIDE.md)。

## 当前运行关系

```text
浏览器 → Vercel → 原固定 HTTPS 隧道 → M1 Max 网站网关 :4327
       → M1 Max BFF :4317 → M1 Max Provider A :3117 → 腾讯 IMA

获授权的私有设备 → Tailscale HTTPS → M1 Max 中转 :4328 → Provider A
```

以上本机端口均监听回环地址。Vercel 沿用原固定隧道地址及网关密钥，不保存账号池，本次无需修改 Vercel 环境或重新部署。公网网关只允许网站静态资源及指定 `/api/qa/` 路由；OpenAI API 不通过 Vercel 开放。

维护者确认 Air 已排空任务并停用旧 Provider、网站及隧道，接收端在明确启动和公网恢复授权后接管。Air 机器人保持原进程，尚未完成新 Provider 的远程接入；旧 Provider 和隧道应继续停用。

## 恢复依据

密文摘要、归档成员安全和全部 210 个清单文件校验通过，运行中的 159 个 Provider／网站固定源码文件与迁移包一致。使用包内固定代码与 Node 22；保留原部署兼容补丁，没有以 GitHub main 或空账号池覆盖。接收端新增托管、中转和网络辅助配置独立维护，未据此发布新稳定镜像。

五个账号及关键密钥保留；原有 20 个 Provider 会话的归属、账号绑定和消息保持，网站原有访客绑定、请求回执、待发消息及任务恢复数据已核对。账号、凭证、私有映射和真实历史留在本机私有树，不进入仓库。无需逐账号重新扫码，迁移登录态可完成本次真实问答；不能据此称五账号均已逐一真实问答通过。

网站 Cookie 签名、Provider 应用身份、服务凭证、会话与任务必须一起保留。更换签名或调用方命名空间可能让旧访客历史不可访问。私有恢复路径以包内映射和实际配置为准。

## 管理后台与维护时间

账号池维护继续使用 Provider A 的 `/admin.html`，默认只在本机维护端口访问，需要独立管理员凭证；普通问答中转、OpenAI 接口及 Vercel 均不开放该管理入口。知天下 `/admin` 是未发布、无鉴权的原型，保持封锁；当前不另建一套账号登录维护后台，网站业务用户／权限等需要出现后再独立规划。

本轮只读确认管理页面和管理员认证的账号查询可用，五个账号均提供上次／下次检查、可续期时间、访问令牌到期、续期凭证到期及上次成功续期；时间格式带浏览器时区。当时没有待重试时间，没有触发刷新、扫码或真实问答。具体值与账号信息不进入此记录。此检查不等于完整管理 UI、重新登录或新资格评测验收。

字段解释和分批维护步骤见 [Provider 后台运维说明](https://github.com/19Chris19/ima-qa-web-agent/blob/main/docs/ADMIN_OPERATIONS.md)。令牌到期不必然要求扫码，不能把成功续期时间当成最后扫码时间，也不能由时间字段保证下一次人工登录日期。安排账号持有人操作前，须先补齐并验收本机扫码与评测依赖。

## 后续迁往正式服务器

这次成功说明：在同一维护者掌控下，停止旧端后，可以整体恢复账号登录态、密钥、网站身份和会话；普通问答无需持续运行扫码浏览器。完整操作顺序见 Provider 的[主机迁移说明](https://github.com/19Chris19/ima-qa-web-agent/blob/main/docs/HOST_MIGRATION.md)。

仍应为目标服务器固定代码、Node 22、锁定依赖和实际数据路径；迁移包有补丁时以包及清单为准，不运行新安装初始化。Linux 不能照搬 macOS 的二进制、依赖目录、LaunchAgent 或网络托管方式。源端所有续期和派发者必须停用并取得切换授权，新端启用后回退需使用最新状态，不能复活过期备份。

IMA 可能因到期、网络改变、知识库权限或风控要求重新登录。此次 macOS 迁移成功不能保证 Linux／Docker／云服务器免扫码，也不代替新账号扫码及维护通路的验收。
