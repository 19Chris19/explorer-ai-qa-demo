# 需求、架构与实施计划

## 产品目标

为知天下 3DGS 主站开发左侧侧边栏中的单页 AI 问答体验。演示版先在独立本地项目验证页面与 Provider A 接入，随后迁入团队主站仓库的功能分支。界面延续主站的浅色、克制的导航和卡片语言，适配桌面与移动端；用户能新建、查看、追问、停止、删除对话并核查来源。普通用户不选择 Provider。

## 技术边界

浏览器只访问同源 BFF。BFF 保存普通 Provider 凭据、映射用户身份、创建/读取/删除会话并转发 SSE。Provider A 是现有 IMA Web Agent 问答服务，演示期主力；Provider B 拟用 IMA 官方 OpenAPI 检索证据并结合自有模型生成；Provider C 拟用 WeKnora 与自有原始资料、索引和模型建立独立知识库。B/C 均尚未接入。管理后台应并入主站现有后台，负责健康、知识更新、权限、告警、成本和审计；包内 `/admin` 仅展示信息架构。

未来路由层应保有与 Provider 无关的业务会话和已完成轮次。故障前若尚未输出正文，可在策略允许时切换；若已有部分正文，不能拼接两个 Provider 的半段回答，应依据已完成历史重整当前回复并明确恢复状态。上下文、来源与失败分类须统一。当前演示版**没有**实现这一层。

## 分阶段实施

1. **演示验收**：稳定本地页面与 BFF，排查 Provider A 的真实首问 SSE 错误；完成同一客户身份和会话 ID 的首问、追问、来源与 `done` 验收。无成功 `done` 不宣布问答可用。
2. **主站集成**：从团队主站共同基线建短期功能分支，迁入页面组件与同源 BFF 契约；以主站登录态替换匿名身份，接入正式设计 Token、权限和审计。保持 token 仅在服务端。
3. **运维面板**：接入经过授权的健康与脱敏状态，增加失败追踪、告警、知识更新与成本；写操作设置角色权限和审计。
4. **B 候选**：验证 IMA 官方接口的证据可读性、额度、模型成本、引用质量与无证据拒答；用固定题集与 A 比较。
5. **C 候选**：从团队自有资料建设可持续更新的本地知识库，验证解析、索引、来源回链、删除同步、备份恢复和脱离 IMA 后的独立问答。
6. **自动切换**：在真实 A/B/C 都通过验收后，实现容量感知、故障分类、业务会话迁移、一次替补上限和中途失败的统一界面体验。

成本估算按基础设施、调用/模型、资料更新、备份和人工维护分别记录；在取得真实用量与合同价格前，不填入臆测金额。详细日常维护与决策门槛见 `PROVIDERS_OPERATIONS.md`。

## 团队协作

此 ZIP 是**源码快照**，不是可合并的 Git 历史。收到主站代码后，先确认默认分支、Node/构建工具、现有鉴权和路由约定；从团队指定基线创建短期功能分支，按页面、BFF、管理面板、测试拆分可审查提交。保持锁文件与源码同步，合并前运行构建和测试并在测试环境验证 SSE；普通 token 通过环境配置交付，不进提交或 PR。正式发布应记录部署版本、健康与真实问答验收、回滚版本。
