# AI 问答三 Provider 方案与运维报告

本报告依据 2026-09-23 的项目检查与 Air 脱敏交接资料。A 已有可运行实例；B 和 C 是后续建设目标。任何“已连接”“已容灾”“已完成同步”状态都应来自实测，不由管理原型推断。

## 1. 目标、职责与当前边界

主站问答页面只处理提问、历史、流式显示、来源和失败恢复。主站服务端持有用户身份及 Provider 凭证，负责把业务会话映射到 A/B/C。运维后台负责健康、账号/凭证、知识更新、任务、告警、成本、审计。普通用户不选择 Provider。

| Provider | 数据与回答路径 | 现状 | 主要维护对象 |
|---|---|---|---|
| A：IMA Web Agent | 已授权 IMA Web 账号 → IMA 原生知识问答 | Air 上运行，演示主力 | 登录态、账号资格、上游变化、队列与会话存储 |
| B：IMA OpenAPI + 模型 | 官方 OpenAPI 检索/读取证据 → 自有模型生成 | 待独立接入与评测 | API 额度、可读取正文比例、模型、证据与引用质量 |
| C：WeKnora 自建库 | 自有原始资料 → 自行解析/索引/检索/生成 | 待部署与建库 | 原文件、同步、索引、模型、存储、备份与服务器 |

C 的长期目标是不依赖 IMA 托管资料或提供问答。WeKnora 虽有 IMA 连接器，但 C 的正式语料应以团队持有的原文件、授权网页或自有系统为准；IMA 同步最多作为迁移期辅助，不应成为唯一更新来源。

## 2. 统一接入与自动切换

服务端维护一个与上游无关的业务会话 ID，持久保存已**完成**的用户问题、助手答案、来源和时间；各 Provider 的 session ID、请求 ID、账号分配只作为内部映射。业务接口至少覆盖创建/读取/删除会话、发送问题、取消、SSE 事件和当前服务状态。来源统一为标题、片段、可访问链接/内部引用、可用性；不能打开的来源应如实提示。

新问题提交前，路由器按健康、容量、近期失败、知识库覆盖和成本策略选 Provider。选中后将该业务会话的已完成轮次映射到上游：A 继续已绑定的 IMA session；B/C 在允许的上下文长度内接收对话摘要与最近轮次，并附带其检索证据。不同 Provider 不共享内部 session ID。每次路由记录提供者、原因、延迟、结果、成本和来源数，但不在普通日志保存密钥或资料原文。

中途失败时，先区分“未输出正文”和“已输出部分正文”。前者可以自动换 Provider 重试；后者在**同一回复位置**显示短暂恢复状态，替换未完成正文，由接替 Provider 基于业务会话已完成历史、当前问题重新回答。不要拼接两个 Provider 的半段输出。恢复最多尝试一次不同 Provider，避免循环和重复扣费；若来源或上下文无法可靠迁移，显示明确失败并保留可重试操作。用户不会选择 Provider，但恢复状态与失败事实可见。若所有 Provider 共享同一 IMA 数据源或模型，视为共同故障，不能宣称独立容灾。

首版演示只有 A 接入。上面这一层是后续契约与验收目标，不是当前已完成的功能。

## 3. A：日常维护、故障和恢复

Provider A 已有独立运行实例，但服务版本、账号资格、默认可调度容量与限流均应由接收方在其获授权的环境中重新核对。健康接口可用于连通性诊断，不能替代真实首问、追问与来源验收。部署前还需核对监听地址和网络访问边界。

| 频率 | 操作 | 记录/通过标准 |
|---|---|---|
| 每日 | 看服务、可调度账号、排队、最近失败；用公开业务问题抽检回答与来源 | 服务通、至少一条可调度路径、来源与目标库相符 |
| 每周 | 对每个账号检查授权与续期状态；复核限流和平均/尾部等待时间；抽查来源失效 | 不把账号总数误作默认并发；异常账号隔离处理 |
| 每月及升级前 | 加密备份私有 `runtime/`、配置和版本清单；隔离环境做恢复演练 | 恢复后账号、会话和可调度容量一致，密钥未出现在日志/Git |
| 每次发布 | 固定版本、运行单元测试、隔离实例真实首问/追问/来源/重启验收，再切流 | 有回滚版本和脱敏验收记录 |

故障定位按顺序检查：隧道和 服务主机网络 → 服务主机供电/睡眠/用户会话 → Node 进程和 `/healthz` → 可调度资格 → IMA 授权/限流 → SSE 结束事件与来源。仅有 `/healthz` 200 不证明知识问答可用。登录失效时在维护端按项目的管理流程重新接入受影响账号；不可把账号库或 token 复制到前端机器。上游私有网页接口变化时，应以独立测试库验证适配，再灰度发布。演练会暂停普通请求，不在有真实流量时启动。

现有演示环境使用用户会话中的 macOS 服务。合盖、睡眠、断电或用户未登录会使服务和 SSH 隧道中断；应接电、核对睡眠策略，正式上线改用有稳定供电/守护的服务器或部署安排，并让隧道自动重连。达到多实例或更大账号池时，需将当前文件状态迁往共享数据库/锁方案并做迁移验收。

## 4. B：官方 OpenAPI + 模型

IMA 官方 Skill `1.1.7` 展示了 `search_knowledge`、`get_media_info` 和笔记正文读取等能力；这条路线从检索证据再生成答案，不是直接调用 IMA 网页原生答案。搜索命中不保证能读到全文。Provider B 要固定服务器端知识库范围，封装查询改写、分页、限流/熔断、正文补全、证据去重、引用校验和无证据拒答。网页不接触 IMA Client ID、API Key 或模型密钥。

日常维护记录：OpenAPI 请求数与额度、429/超量、检索召回率、可读取正文比例、模型 token、来源错误率和 30–50 个代表问题的人工评分。遇额度用尽立即熔断，停止自动扩查询与补全文，展示服务繁忙并视策略转到真正独立的 C。来源不足时不能让模型靠提示词补出原文；先检查权限、数据可读性和召回。官方接口或响应字段变更时用固定测试集回归。密钥轮换先在隔离环境验证权限和知识库 ID，再切换生产配置。

## 5. C：自建 WeKnora 知识库

从团队有权保存的原文件建立清单，记录来源、所有者、许可、版本、校验和、更新时间和删除规则。上传新资料先进入暂存区，完成病毒/格式校验、解析、OCR/图像描述、分块、Embedding 和索引，再抽查文本与来源回链；检查通过后切换可检索索引版本。失败资料保留原因和重试任务，删除或撤权需同步从索引、缓存和备份策略中处理。

首轮用一小批有标准答案的 3DGS 资料试点，记录初次建库时长、不可解析占比、召回与引用质量。更新采用增量优先、定期全量对账；定期核对原文件数、成功索引数、待处理数、删除数和最长更新延迟。同名替换、原文无更新戳、图片/视频无法读正文需要专项验收。数据库、对象存储、模型配置和索引必须有一致的加密备份与恢复演练；不能只备份文档而丢失元数据和向量索引配置。

WeKnora 提供知识问答 SSE、来源与管理能力，也有 IMA 数据源连接器；该连接器会跳过不能读取正文的 AI 会话与视频资料。自建库的价值在于掌握原始资料与更新链路，不能只把 IMA 不完整搜索结果复制到本地就算独立。服务器容量由资料体量、解析峰值、并发数和模型部署方式决定，应实测后选型。

## 6. 管理后台与权限

管理后台建议并入主站现有后台，分为总览、Provider、知识库、运行维护和成本五区。本地 `/admin` 仅是信息架构原型：只读 A 基础健康，其余明确标记未接入。正式后台分角色授权：观察者看脱敏指标；运维人员可重试任务、暂停 Provider 和处理账号；超级管理员可轮换凭证、改路由策略或删除资料。所有高影响操作记录操作者、时间、对象、前后状态和结果。

总览显示可用 Provider、当前主用路径、可调度容量、队列、成功率、P95 首字/总时延和近24小时故障；Provider 页看凭证到期/额度/冷却和降级原因；知识库页看同步、解析、索引版本与无法读取资料；运行页展示告警和脱敏请求追踪；成本页展示用量、预算、单问成本及预测。告警应有责任人与处理手册，重点是全 Provider 故障、A 可调度数下降、B 额度熔断、C 更新延迟/索引失败和来源缺失率升高。

## 7. 成本模型与决策门槛

价格与实际用量尚未确定，因此用公式而不是臆测金额。管理后台按每日、每月和单问记录真实用量，再乘采购合同中的单价。

| Provider | 一次性成本 | 持续成本与计量 |
|---|---|---|
| A | 接入、真实验收、监控与账号池配置 | 工作站/服务器、网络、电力、账号维护人工；按成功问答、排队时间、登录故障统计 |
| B | 检索/证据封装、模型集成、基准题库 | OpenAPI 请求和额度、补全文请求、生成模型输入/输出 token、人工质量复核 |
| C | 原始资料治理、首次解析/OCR、Embedding 与索引 | 新增/改动资料的解析与重新向量化、模型生成与重排、数据库/对象存储、备份、计算资源、运维人工 |

建议按 `每月总成本 = 固定基础设施 + 调用计费 + 数据更新处理 + 备份存储 + 运维人工`，再以 `成功且通过质量检查的问答数` 计算有效单问成本。C 的首次建库费用与每月维护费用分开；B/C 若使用云模型，应分别计算输入、输出及嵌入 token。上线决策同时比较质量、覆盖、可用性、首字时延、P95 总时延和有效单问成本，不只比较模型单价。

## 8. 阶段验收

1. **A 演示**：跨机 SSH 隧道、健康、同一客户会话首问/追问、相关来源、SSE `done`、浏览器不接触 token；单账号失败时页面有明确状态。
2. **B 候选**：用固定题集比较 A 的核心事实、引用与拒答；验证额度熔断、密钥轮换、无可读正文和模型故障。
3. **C 候选**：从自有原文件独立建库，验证新增/变更/删除同步、来源回链、备份恢复和断开 IMA 后的持续问答。
4. **自动切换**：断开各 Provider、让回答生成中途失败、重复提交和恢复；确认业务会话连续，半段答案被同位重整，最多一次替补，失败记录可追踪。
