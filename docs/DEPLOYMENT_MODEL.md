# 双仓关系与配套发布

## 对外怎么讲

Provider A 是通用知识库问答服务；知天下是调用它的网站产品。用户只选择一个产品入口，部署知天下时工具负责准备配套 Provider。账号扫码、手机确认、知识库加入仍由人完成，不随源码交付现成账号。

```text
浏览器 -> Nginx -> 知天下 BFF -> Provider A -> IMA
          ^            ^            |
          +------ 流式回答返回 -------+
```

普通访客只连接网站。BFF 用自己的普通凭证读取会话历史，用服务凭证请求受保护的容量/流式接口；管理员凭证只用于维护，不参与网站问答。Nginx 拒绝管理和内部路径。两个服务在私有容器网络通信，网站数据和 Provider 账号/会话分别持久化。

## 默认拓扑

一个新 Compose 项目启动独立 Provider、网站和网关，生成新配置与空账号池。不用 host 网络，不读取开发者 Air 的账号、会话或签名。端口冲突或已有配置时停止，不覆盖。默认入口仅监听本机，服务器公网域名和 HTTPS 是后续明确的运维配置。

2026-10-06 孤立资源保护：统一 `onboard init`、`deploy.sh init` 和旧的 `npm run docker:start` 不以“没有容器”判定空项目。它们还检查 Compose 项目标签下的卷/网络，以及将使用的同名 `PROJECT_provider-state`、`PROJECT_explorer-state`、`PROJECT_backend`（即使没有标签）。发现任一资源或查询失败即停止，不读取卷内容、不清理、不重置账号和网站队列。不要删除这些资源以绕过检查；新建安装选择全新的项目名。已有安装保留原配置和数据，按原记录执行 resume/维护；统一入口额外要求 `deployment.json` 项目与 `release.env` 一致，沿用既有配套版本及工具来源校验。init 即便发现元数据也不会自动接管，避免把旧数据当新安装。

共享 Provider 是高级选项：网站与机器人独立身份和业务凭证，但共享账号并发、调度、上游故障与维护窗口。各方不得直接挂载同一个账号目录。共享需要明确容量和维护责任，不是默认省略安装的方法。

## 配套版本只有一个来源

`deploy/bundle.env` 保存候选/已发布状态、网站版本、Provider tag。Shell、PowerShell、Node 安装器与镜像发布记录都从它读取，不分别挑两个仓库的 latest。

新安装解析这对固定版本镜像，生成 `.docker-lab/deployment.json` 与 `release.env`，保存实际镜像摘要（无注册表摘要的本地候选保存 image ID）、代码 revision 和配套版本。后续 resume 使用这些已固定值，不重新追随版本 tag。这些安装记录不含凭证值，但仍保留于私有目录。

2026-10-06 候选修正：`deploy/onboard.mjs` 与 `deploy.sh` 的每次 Compose 调用都从 `release.env` 显式绑定项目，清除继承的 `COMPOSE_*`、镜像、revision、端口和 `DEMO_ASSET_PREFIX` 插值变量，但保留 Docker 连接与授权设置。初始化时的镜像环境变量只用于选择待检查的镜像；不能覆盖后续安装锁。锁文件只接受生成的六个字段及不可变 digest/image ID，缺失、重复、浮动 tag 或非法值都会停止，不执行锁文件内容。网站升级和回退逐次读取更新后的锁文件，不重新采用 shell 中的旧镜像变量。高级自定义 Compose 配置需另有明确维护流程，不能靠环境变量暗中覆盖此入口。

发布检查与网站服务一致：只有显式设置 `PROVIDER_A_ALLOW_HOST_GATEWAY=true` 才允许已有文档规定的 `http://host.docker.internal:3117`；未授权及其他地址仍拒绝，默认独立 Provider 拓扑不变。合成 CI 显式提供 `PROVIDER_IMAGE=node:22-bookworm-slim`，用于基础 Compose 插值，不代表生产 Provider 镜像。

本次证据仅为临时合成配置、假 Docker 命令及本地 Node 测试/源码构建；没有调用 Docker daemon、访问既有配置或验证 Windows/远程 Linux 的实际运行。此前候选运行证据仍按原日期和范围解释。

正式镜像流水线在两架构启动验收后生成 `release-manifest.json`，记录网站和 Provider 的摘要、提交、合同与合成验收边界。不能用本地 image ID 冒充 GHCR 发布摘要。tag 必须保持不变；升级网站不会自动升级 Provider。

## 闭环验收分开报告

1. 安装完成：服务启动、凭证和合同通过，空池容量 0 是正常但不可问答。
2. 接入完成：扫码和目标库权限通过，账号可调度。
3. 合成链路：网页/BFF/模拟 Provider 的流式、历史、来源、取消和排队通过，不表示 IMA 可用。
4. 真实链路：授权窗口中完成一问一追问，检查正文、来源、唯一完成态和刷新历史，才报告本次真实问答通过。

回退只恢复代码/镜像，继续使用当前数据；不能用旧卷覆盖新会话。新环境必须有自己的凭证和数据，不能靠复制 Air 配置来实现“开箱即用”。
