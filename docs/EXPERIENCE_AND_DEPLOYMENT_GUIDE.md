在线入口：[知天下 AI 问答](https://explorer-ai-qa-demo.vercel.app/)。不需要安装软件、取得 GitHub 权限或扫码 IMA。实际服务已由 Air 迁到 M1 Max，Vercel 继续作为公网入口。

2026-10-12 已通过完整公网链路的真实首问、同会话追问、流式返回、上下文保持和重新读取历史。首问约 20.6 秒、追问约 8.8 秒；这是当次测试耗时，不是响应时间承诺。首页及服务健康也已重新检查。当前观察到可调度容量为 5，尚未逐账号完成真实问答，也未做并发压力验收。证据与限制见[迁移验收记录](HOST_MIGRATION_20261012.md)。


本次问答交互：蓝色角标是网页来源，桌面悬停可看文字依据，手机点按打开对应来源的底部面板，再点卡片访问网页。绿色知识库角标保持静态，不显示内部内容或跳转。封面仅为匿名网页声明的分享图；两秒内无法完成就只保留文字，不自动重试。复制表格、下载 CSV 和代码复制使用图标；答后追问仅在上游提供时显示，点选填入草稿，不自动发送。

供转发的体验说明：

> 请打开上面的链接，先新建会话，做一次知识库相关的文字提问，再在同一会话追问。可以查看流式回答、Markdown、表格、来源入口和自己的历史。每次先少量串行体验，回答需要等待。短暂断线时先回到原会话查看原任务，不要连续重发。遇到问题请记录时间、设备、网络和操作步骤，不发送密码、Cookie 或真实敏感内容。这是共享账号池的体验服务，可能受机器、网络、隧道、登录状态和上游限制影响，尚不承诺全天候在线。

本次公网测试使用维护机已有的网络代理。其他设备、移动网络及不同地区访问仍待同事反馈；不能据此承诺国内所有网络均可访问。同事无需按本指南安装代理；遇到访问失败先反馈网络信息。公开链接本身没有网站登录访问控制，请先在受邀同事范围内体验，不投放大规模流量。

## 三种方式怎么选

| 方式 | 当前可交付的内容 | 使用限制 |
| --- | --- | --- |
| 直接在线体验 | 打开现有 Vercel 链接，由 M1 Max 的网站 BFF 和 Provider A 提供问答 | 已通过上述真实问答；重启、长期运行、跨设备网络与并发压力仍待验收 |
| 部署自己的网站，接入维护者的共享 Provider | 暂未向同事开放 | M1 Max 已有 Tailscale 私有入口和鉴权中转，但远端设备、调用方授权、历史身份及真实问答未完成接入验收；不能直接照稳定版安装共享模式 |
| 完整独立部署，使用自己的账号 | 固定稳定 Release、配套 Docker 镜像及 Agent 引导工具 | 可作为部署测试；全新机器扫码到首问／追问、Windows 真机、Linux SSH 扫码与长期运行尚未全部验收，不保证开箱即用 |

独立部署需要你自己的 IMA 账号和目标知识库权限。维护者的账号、密钥、会话与迁移包不会提供给同事。已有服务迁移是原维护者的专门维护流程，不能用它代替新用户接入自己的账号。

只需要通用知识库问答而不需要知天下品牌网站的人，可以单独部署公开的 Provider A。

## 地址与运行关系

- 网站私有仓库：[19Chris19/explorer-ai-qa-demo](https://github.com/19Chris19/explorer-ai-qa-demo)
- Provider A 公开仓库：[19Chris19/ima-qa-web-agent](https://github.com/19Chris19/ima-qa-web-agent)

```text
当前在线体验：
浏览器 → Vercel → 固定 HTTPS 隧道 → M1 Max 受限网站网关
       → M1 Max 网站 BFF → M1 Max Provider A → 腾讯 IMA

独立部署：
你的浏览器 → 你的网站 / BFF → 你的 Provider A → 腾讯 IMA

受邀共享（仍待开放）：
你的 BFF / 设备 → 经批准的私有网络与专属鉴权 → M1 Max 中转 → Provider A
```

Vercel 不保存账号池。浏览器不取得 Provider 密钥，也不能访问管理接口。网站与 Provider 各自保存自己的私有配置与运行数据，通过接口连接。Air 上的旧 Provider、网站和隧道保持停用；Air 机器人尚未切换到新机。

本机新增的 OpenAI Chat Completions 文本中转目前只在本机／获授权的 Tailscale 网络内提供，不从 Vercel 网站向公众提供 API。外部用户的网络批准、专属密钥和远端验收仍待完成；它不是完整 OpenAI 功能、计费系统或可直接分发给同事的共享套餐。

## 已有服务迁移与登录态

这次 Air → M1 Max 恢复没有逐账号重新扫码，迁移登录态可以继续完成真实问答。完整恢复必须一起保留固定代码、加密账号库与解密密钥、服务凭证、Provider 会话和任务、网站 Cookie 签名、访客归属、队列及任务恢复记录，并按新路径核对。仅复制账号 JSON 或重新生成签名密钥会破坏恢复。

**这证明迁移已有有效登录态可行，不证明今后迁往 Linux、Docker 或云服务器一定免扫码。** IMA 可能因到期、网络变化、权限或风控要求重新登录；目标平台需单独验收。新系统也要重新准备匹配的 Node 22、依赖、进程托管和网络入口，不能直接运行旧机器的二进制或 `node_modules`。

同一组账号只能有一个续期和派发任务的运行端。先排空、停止旧服务及自动重启，确认切换授权后才能启动新服务。不要运行全新初始化、空账号池安装器或用 GitHub main 覆盖带补丁的迁移代码。具体流程见[迁移记录与后续服务器门槛](HOST_MIGRATION_20261012.md)。

现有五账号继续使用。本机已补齐匹配的扫码浏览器与资格评测题库，并完成受控重启；真实重新扫码、新账号接入及资格评测仍须单独验收，不能以依赖就绪代替登录和问答资格通过。

## 管理后台和后续账号维护

普通体验者不需要管理权限。维护者统一使用 **Provider A 账号管理后台**，默认本机地址 `http://127.0.0.1:3117/admin.html`；部署在其他主机／端口时以实际配置为准，远程维护通过经批准的安全管理通道。不要向同事分发管理员 token，也不要经 Vercel 或普通问答中转开放管理接口。

后台可查看知识库资格、登录状态及上次／下次检查、可续期时间、访问令牌到期、续期凭证到期和上次成功续期，用于组织一批账号的维护。显示时间需核对浏览器时区；未知时间不推算。**短期令牌到期不等于必须扫码，上次成功续期不等于最后扫码，不能承诺某个固定的重新登录日期。** 结合续期结果和明确错误分批安排持有人操作，不同时停掉全部可用账号；具体步骤见 [Provider 后台运维说明](https://github.com/19Chris19/ima-qa-web-agent/blob/main/docs/ADMIN_OPERATIONS.md)。

知天下 `/admin` 只是无管理员鉴权的原型，当前没有可正式使用的网站业务管理后台，公网保持封锁。账号池维护直接使用 Provider A 即可；未来如需网站用户、权限、业务配额或审计，再建设单独的业务后台，网站访客归属及任务记录仍由网站负责。本机后台与维护时间的只读检查通过，但安排重新扫码前仍须准备并验收上一节所述的浏览器和资格评测依赖。

## 使用 Agent 协助部署

仅在线体验的同事不需要以下提示词。愿意参与独立部署测试时，再将它交给具备终端能力的 Agent：

```text
请协助我体验或部署知天下 AI 问答。
网站私有仓库：https://github.com/19Chris19/explorer-ai-qa-demo
Provider A 公开仓库：https://github.com/19Chris19/ima-qa-web-agent
在线体验：https://explorer-ai-qa-demo.vercel.app/

先确认我选择哪种方式，再安装软件；我已明确选择时不重复询问：
1. 在线体验：只打开网页，不下载仓库、不安装服务、不扫码账号。
2. 部署网站并接入维护者的共享 Provider：暂未开放。说明限制，等待维护者给出固定候选、网络批准及安全配置，不执行共享安装，也不自动改选独立部署。
3. 完整独立部署：网站及配套 Provider 使用我自己的 IMA 账号，推荐 Docker；这是需要单独验收的部署测试。
4. 如果我明确要求迁移自己的已有服务：先走包内迁移清单和 docs/HOST_MIGRATION_20261012.md，不运行新安装初始化。未经明确停旧与切换授权，不启动新的续期或任务派发端。

部署时阅读 README、docs/AGENT_DEPLOYMENT.md 和对应稳定 Release；按 deploy/bundle.env 及镜像摘要固定配套版本，不用浮动 main/latest。不要把迁移成功当成全新安装或跨平台免扫码保证。

先检查系统、架构、端口、已有安装、源码和私有镜像权限、Docker daemon 与 Compose。缺少软件时解释官方安装内容，按我的授权处理；密码、2FA、扫码、手机确认及系统安全授权由我本人完成，不索要聊天中的 token，不绕过系统策略。

独立部署使用仓库 onboard 工具，预设知识库为“3DGS 知识答疑”；提醒我使用已加入目标知识库的账号。Linux 通过我授权的维护电脑与 SSH 维护，账号存我的服务器。不复制维护者账号、密钥或历史。源码权限与 GHCR 镜像权限分别核对；失败时不借用他人凭证或未知镜像。

保留已有配置、账号、会话与数据卷，不重新生成密钥，不公开 /admin、/internal/ 或凭证，不自动重发未知提交。恢复原任务使用原身份与幂等键。健康检查不提问；真实一问一追问先说明并取得我的授权。

最后分别报告版本／镜像、地址、安装、连通、账号状态、真实问答、恢复方式和未验收项。保留共享远端未验收、全新扫码、Windows、Linux、手机与主站、长期运行等边界；不把维护者的历史证据当成本机通过。不自动购买付费服务。
```

如需源码，申请并接受私有仓库邀请，在本机浏览器人工登录和完成 2FA。私有 GHCR 镜像权限另行核对。公开 Provider 源码不需要网站私有权限；在线体验无需 GitHub 登录。

## 体验反馈与结果判断

已通过的基线是短首问、同会话追问、流式返回、上下文与历史。长问题、长表格及来源质量、真实断网续接、排队／编辑／取消、手机输入可作为探索性体验，出现问题应记录，不能说本轮已全部验收。

- 安装完成不代表账号可问答；健康检查不代表真实问答成功。
- 同次真实问答通过不覆盖其他平台、网络、账号、并发及长期运行。
- 断流、等待或结果不确定时先读原任务和历史，避免重发产生第二次上游调用。
- 反馈请给时间、设备、网络、使用方式和复现步骤，可附脱敏截图；不要提供密码、token、Cookie、扫码凭证或私人问答。

**只看效果，先在线体验；愿意协助部署验证，再做完整独立部署；共享接入等待开放通知。**
